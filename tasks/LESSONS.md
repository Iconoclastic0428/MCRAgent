# Lessons

- 2026-05-25: For Chinese-Standard-Mahjong/MCR policy code, never allow `HU` from a complete-hand check alone. `HU` is legal only when the official fan requirement is satisfied. If the official fan checker is unavailable in a runtime artifact, suppress `HU` rather than risking `WH` penalties.
- 2026-05-25: Treat unknown fan as not enough fan. The bot must wait instead of emitting `HU` unless the full model's official checker or the source package's conservative lower-bound gate proves at least 8 fan.
- 2026-05-26: For draw-policy rule construction, optimize toward a stable >=8-fan structure with the most live waits. Ignore incidental fan sources such as last-tile draw/discard, robbing a kong, and after-kong draw when evaluating future structure; prefer discards that improve fan-valid tenpai waits, then first-class effective tiles that reduce shanten while preserving an 8+ fan path, then second/third-class effective tiles that increase the count of stronger effective tiles without worsening shanten.
- 2026-05-26: The previous >30-hour MCR model-search path failed because it treated supervised/RL artifacts, offline accuracy, and small official win-rate bumps as progress before making the core MCR effective-tile rule a hard policy invariant. The bad pattern was repeatedly training around proxy labels and then adding fan/effective-tile logic as an overlay; that lets the model choose tiles that do not preserve a stable >=8-fan path with maximum waits, so the resulting policy is strategically meaningless even when it occasionally wins an official sample-bot slice. Future work must start from the effective-tile hierarchy as the base decision rule, use Lawlorentz-style masked actions/state structure only after that rule is implemented, and discard any learned component that overrides the rule or reaches for `HU` without proven >=8 fan.
- 2026-05-27: For CHAGA imitation work, treat PLAY exact tile agreement as the primary replay metric. Overall exact/action-type/Hu agreement can be useful for diagnostics, but they do not prove the model is learning CHAGA's discard/play choices; training and sweeps should rank candidates by held-out CHAGA PLAY exact rate first, then check official-judge play strength separately.
- 2026-05-27: For NRP L40/L40S training, only request GPU allocation through Kubernetes jobs/pods. Do not use the NRP/Airtable reservation form for this workflow; if L40/L40S is unavailable, leave the Kubernetes job queued and check it on the requested cadence.
- 2026-05-27: For CHAGA review evaluation, do not report recorded player action vs CHAGA candidates as model strength. The meaningful metric is model-predicted action vs CHAGA review candidates; only for a single player's first six discard/PLAY decisions may top-3 count as a match, otherwise use top-1.
- 2026-05-27: For tziakcha dataset expansion, do not treat CHAGA02-08 or current-leaderboard-only slices as sufficient. Build the corpus from all available tziakcha records that include any player whose session-time ELO is greater than 2300; use the current leaderboard only for explicit current-ELO experiments, and document any public-archive gap before calling the dataset complete.
- 2026-05-27: For the CHAGA benchmark split, do not train only on CHAGA-reviewed rows. Training must include all eligible record-local `>2300` tziakcha players as supervised targets; CHAGA review rows are the validation/test target for candidate-match precision and may be used as additional teacher/distillation signal without replacing the all-player high-ELO training corpus.
